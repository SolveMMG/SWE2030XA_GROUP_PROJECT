# SkillSwap

A micro-freelance skill exchange marketplace for university students. Students list services they offer (tutoring, design, tech support, proofreading) and hire other students for tasks — all verified through university Google accounts.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React.js, HTML5, CSS3 |
| Backend | Node.js, Express.js, REST API |
| Database | PostgreSQL |
| Auth | Google OAuth 2.0, JWT, Bcrypt |
| Media | Cloudinary |
| Email | Nodemailer |
| DevOps | GitHub Actions, Docker, Render |

## Getting Started (local dev)

1. Copy the environment file and fill in your values:
   ```bash
   cp .env.example .env
   ```

2. Start all services with Docker:
   ```bash
   docker compose up --build
   ```

   | Service | URL |
   |---|---|
   | Client | http://localhost:3000 |
   | Server | http://localhost:5000 |
   | Postgres | localhost:5432 |

## CI/CD

**CI** runs on every push and pull request to `main`/`develop`:
- Lint and test the server (with a live Postgres service container)
- Lint and test the client
- Verify both Docker images build cleanly

**CD** runs after CI finishes on `main` (via `workflow_run`, gated on CI success):
- Triggers Render deploy hooks for the server and client services

Render's own auto-deploy-on-push is intentionally left off (`autoDeployTrigger: off` in `render.yaml`) so a broken build never reaches production — only a green CI run on `main` can trigger a deploy.

### First-time Render setup

1. In the Render dashboard: **New → Blueprint**, connect this repo. Render reads `render.yaml` and provisions `skillswap-db` (Postgres), `skillswap-server` (Docker web service), and `skillswap-client` (static site).
2. During blueprint creation, Render prompts for every env var marked `sync: false` in `render.yaml` — fill in your real Google OAuth, Cloudinary, and Gmail app-password values there. `JWT_SECRET`/`JWT_REFRESH_SECRET` are auto-generated by Render; nothing to enter.
3. `CLIENT_URL` and `GOOGLE_CALLBACK_URL` are pre-filled assuming the service names above are free on Render. If Render assigned different hostnames (name collision), update those two env vars on `skillswap-server` to match.
4. Add the production redirect URI (`https://skillswap-server.onrender.com/api/v1/auth/google/callback`, or your actual server URL) to the OAuth client's **Authorized redirect URIs** in Google Cloud Console.
5. Grab each service's **Deploy Hook** URL (service → Settings → Deploy Hook) and add them as the two GitHub secrets below.
6. Migrations run automatically before every deploy via `preDeployCommand` on the server service — no manual step needed.

### Required GitHub Secrets

| Secret | Description |
|---|---|
| `RENDER_DEPLOY_HOOK_SERVER` | Render deploy hook URL for the backend service |
| `RENDER_DEPLOY_HOOK_CLIENT` | Render deploy hook URL for the frontend service |

Add these under **Settings → Secrets and variables → Actions** in the GitHub repo.
